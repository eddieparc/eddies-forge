# 동기화 명세

상태: 제안. 이 문서는 구현 완료를 나타내지 않습니다.

## 공통 구조

```text
기기 A의 앱 <-> 로컬 어댑터 <-> 동기화 엔진
                                   |
                         승인된 Tailscale 피어
                                   |
기기 B의 앱 <-> 로컬 어댑터 <-> 동기화 엔진
```

클립보드와 비밀번호는 각각 켤 수 있는 독립 기능으로 설계합니다.
전송 경로는 tailnet 내부로 제한하고 공개 인터넷 수신 포트나 Funnel을 기본 경로로 사용하지 않습니다.
Tailscale의 전송 암호화와 별개로 저장 데이터 암호화, 기기 승인, 접근 범위,
기기 분실 시 권한 회수와 키 교체 방식을 구현 전에 결정합니다.

## Clipboard Bridge

### 범위

- 신규 복사 이벤트 전달과 기존 Raycast 기록 이전을 구분합니다.
- 기기·이벤트 식별자로 재전송을 멱등 처리합니다.
- 동일 내용을 사용자가 다시 복사한 경우와 동기화 루프를 구분합니다.
- 파일 경로를 다른 기기에 그대로 복사한 것을 파일 동기화로 간주하지 않습니다.
- 삭제 이벤트와 보관 기간 만료를 구분하고 오프라인 기기에서 삭제 항목이 부활하지 않게 합니다.
- 원격 기록 수신이 사용자의 현재 클립보드를 자동으로 덮어쓰는지는 명시적 설정으로 결정합니다.
- 비밀 표시가 있는 항목은 제외하고, 비밀 표시가 없는 모든 비밀번호까지 자동 판별한다고 약속하지 않습니다.

### 검증 과제

Raycast 공개 API로 최근 항목을 읽는 기능은 전체 기록 열람·삽입 API와 다릅니다.
전체 기록, 원래 복사 시각, 원본 앱, 이미지, 고정 상태를 보존할 수 있는지 각각 확인합니다.
프로필이나 실행 중 데이터베이스 전체를 덮어쓰는 방식은 사용하지 않습니다.
지원 경로가 없으면 그 제약을 공개하고 신규 클립보드 전달과 전체 기록 동기화를 구분해 표시합니다.

### 완료 기준

- 두 실제 기기에서 A→B와 B→A 전달을 관찰합니다.
- 수신·재전송·앱 재시작 후 중복과 루프가 발생하지 않습니다.
- 오프라인에서 발생한 이벤트가 재연결 후 유실 없이 반영됩니다.
- 승인하지 않은 기기는 접근할 수 없습니다.
- 제외 항목이 전송되지 않고 삭제·보관 기간 정책이 일관되게 적용됩니다.
- 전체 기록 동기화를 지원한다고 표시하려면 현재 클립보드뿐 아니라 기존 기록 보존을 입증합니다.

## Credential Bridge

### 어댑터 검증표

| 저장소 | 공식 문서에서 확인한 경로 | 구현 전 확인할 사항 |
| --- | --- | --- |
| Aside Vault | 가져오기·내보내기, 자체 동기화 설정 | 지원 API, 변경 알림, 항목별 읽기·쓰기, 잠금·사용자 승인 |
| Chrome | Apple 확장을 통한 iCloud 비밀번호 사용 | Chrome 자체 저장소의 지원 인터페이스와 변경 감지 |
| iCloud 키체인 | Apple 확장을 통한 Chrome 연동 | 제삼자 도구의 허용된 읽기·쓰기 범위와 변경 감지 |

Apple 확장과 Aside의 문서상 기능만으로 세 저장소 전체의 실시간 병합을 보장할 수 없습니다.
macOS에서 일반 Keychain API를 사용할 수 있다는 사실만으로 Apple Passwords의
모든 항목에 접근할 수 있다고 가정하지 않습니다.
지원되지 않는 경로는 잠금·권한 우회나 원본 DB 직접 수정으로 대체하지 않습니다.

### 마지막 사용자 변경 판정

1. 초기 연결에서는 각 저장소의 기준 스냅샷과 항목 대응 관계를 확정합니다.
   가져온 순서를 기존 항목의 실제 수정 순서로 간주하지 않습니다.
2. 어댑터는 항목의 추가·수정·삭제를 마지막 확인 버전과 비교합니다.
   읽기·자동 완성·파일 접근만으로 사용자 변경을 생성하지 않습니다.
3. 동기화 엔진은 원본 기기, 저장소, 이벤트 ID, 부모 버전과 적용 이력을 보관합니다.
   항목 대응 키에는 저장소별 ID, 정확한 origin, 사용자명 등을 검토하며 서로 다른 계정을 합치지 않습니다.
4. 이미 적용한 이벤트가 어댑터에서 다시 관찰되면 사용자 변경으로 재전파하지 않습니다.
5. 앞선 버전에 대한 후속 수정이 확인되면 새 버전을 적용합니다.
   기기 시계나 파일 수정 시각만으로 순서를 정하지 않습니다.
6. 서로의 변경을 보지 못한 동시 수정은 충돌로 보존합니다.
   실제 수정 순서를 확인할 수 없는 경우 임의로 승자를 정하지 않습니다.
7. 삭제는 별도의 tombstone으로 기록합니다. 삭제와 수정의 충돌도 사용자 선택으로 해결합니다.

항목별 신뢰할 수 있는 버전이나 변경 감지가 없는 어댑터는 자동 동기화 가능으로 표시하지 않습니다.
사용자가 승인한 가져오기·내보내기는 수동 모드로 별도 표시합니다.
잠긴 저장소는 대기 상태로 표시하고, 해제 후 기존 기준과 다시 비교합니다.
인증·권한 실패, 지원하지 않는 앱 버전, 오프라인, 충돌을 서로 다른 상태로 제공합니다.

### 완료 기준

- 각 저장소에서 사용자가 변경한 테스트 계정이 다른 두 저장소로 반영됩니다.
- 새 항목·수정·삭제·동시 수정·오프라인 재연결·시계 오차를 검증합니다.
- 동기화 쓰기가 다시 사용자 수정으로 인식되지 않습니다.
- 잠금이나 권한 실패 시 성공으로 표시하거나 다른 저장소를 빈 상태로 덮어쓰지 않습니다.
- 작업 도중 종료되어도 재실행 시 변경을 유실하거나 중복 적용하지 않습니다.
- 충돌 해결·잘못된 병합 복구·삭제 항목 재등장 방지를 검증합니다.
- 테스트에는 합성 계정만 사용하며 평문 비밀번호가 로그·진단·저장소에 남지 않습니다.

## 구현 착수 조건

각 어댑터의 앱·OS 버전, 권한, 읽기·쓰기·관찰 결과를 기록합니다.
공식 연동 가능 여부를 확인한 뒤 언어·패키지 구조·배포 방식을 선택합니다.
위 완료 기준은 아직 실행하지 않았습니다.
